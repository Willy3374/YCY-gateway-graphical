### 积木规范（约定，勿杜撰 opcode）
- 字段：opcode(snake_case) / category / inputs[{name,type,default,options}]
- 类型：number | string | boolean | enum | variable | condition_block | statement_block
- 输出 JSON：`{version:"1.0", program:[...], variables:{}}`
- **嵌套用 body / else（数组），线性顺序用 next（对象）**，条件/运算/值以内联对象嵌进 inputs 并带 `returns`
- 条件/运算/值积木**不单独成块**，只作内联对象
- 默认值：ID=1，强度=0，时间=1 秒
- 事件积木只能在顶层且各自开新链；数字槽只收 returns=number，条件槽只收 returns=boolean

### 踩过的坑（重要，别重复）
- **顶层拖放顺序反**：`insertionIndex()` 只从 `listEl.children` 取子块，但顶层画布没有独立 `.list` 容器（`listEl === null`）→ `kids` 恒空 → 索引恒 0 → 每块都插到最顶端。修法：`blockElsIn(listEl || rootEl)`。抽出纯函数 `insertIndexFromMids(mids, clientY)` 便于测试。
- **`importNode` 不认识 `next`**：附件程序整条主链靠 `next` 串联，原实现只读 body/else，载入后只剩第一块。已改为沿 `next` 展开成线序（加 5000 深度环保护）。
- **`GPDevice.init` 监听泄漏**：每次 init 都给刷新按钮再加一个 click 监听。改为模块级 `probe` + `refreshBound` 守卫，只绑一次。**测试抓出来的真 bug，不是测试问题。**
- **PowerShell 引号地狱**：内联 `node -e "..."` 里的中文/引号会被 GBK 与转义搞崩（多次误判为产品问题）。教训：验证逻辑一律写成 `tools/*.js` 文件再跑，别用内联脚本。
- **`tools/serve.js` 缺 `.jpg` MIME**：logo 被当 octet-stream 发。
- **读图限制**：当前模型不支持图片，`read` 图片会提示 omitted — 改用像素采样（System.Drawing）判断图内容。

### 真 bug（本轮抓到的，别重复）
- **顶层积木再次拖动从未生效**：`handleDrop` 自环检查 `inListSubtree(b, tgt.arr)` 把顶层移动误判为「拖入自身」（state.root 本来就含这块）→ 直接丢弃。修法：自环检查只针对嵌套列表（body/else，用 `listEl.dataset.owner` 找宿主块），顶层根列表（`tgt.arr === state.root`）放行；同列表内移动靠 `oldIdx < idx → idx -= 1`。**教训：只测「从工具箱拖入」测不出「已摆放块再次拖动」，两个场景都要测。**
- 反向验证：旧判定放回 → 测试确实 FAIL，确认测试有效。
